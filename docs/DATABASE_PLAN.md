# 데이터베이스 및 오프라인 동기화 계획

작성일: 2026-10-05

상태: 첫 APK 출시 기준 설계. 서버, 로그인, 관리자 화면은 아직 구현되지 않았다.

## 1. 목표와 현재 상태

- 학습 기록을 휴대폰에 저장해 인터넷 없이도 이어서 공부한다.
- 로그인 후에는 같은 기록을 서버에도 저장해 다른 휴대폰에서 복원한다.
- 관리자가 시험 일정과 접수 기간을 수정하면 앱을 다시 설치하지 않아도 반영한다.
- 관리자가 수업·단어·문제·해설을 게시하면 앱이 새 버전을 내려받는다.
- 사용자 수가 늘어도 학습 콘텐츠를 사용자마다 복사하지 않는다.

**출시 기준:** 설치 방식은 APK 직접 설치이지만, 첫 APK부터 서버 DB·선택적 로그인·관리자 페이지·콘텐츠/일정 API·기기 내 저장·학습 기록 동기화가 동작해야 한다. 첫 진입 화면에서 로그인 없이 시작할 수 있고, 계정 연결은 설정에서 할 수 있다. 아래 구현 순서는 개발 순서이지 기능을 제외한 APK를 먼저 배포한다는 뜻이 아니다. 현재 저장소에는 Expo 앱 화면과 2026년 시험 일정 상수가 있다. 게스트 온보딩과 일부 학습 점수·표시의 기기 내 저장은 구현했다. 실제 로그인, 서버 API·DB, 관리자 화면, 계정 간 학습 기록 동기화는 아직 없다. 서버 제품과 로그인 방식은 구현 전에 확정한다.

## 2. 데이터가 놓이는 곳

| 위치 | 저장할 것 | 역할 |
| --- | --- | --- |
| 앱에 포함된 자료 | 검수한 시작 수업·문제·필수 음성·일정의 초기 사본 | 첫 설치 직후 오프라인에서도 학습할 수 있는 기본 자료 |
| 휴대폰의 앱 전용 SQLite | 내려받은 콘텐츠·일정, 학습 진도·답안·복습 상태·목표, 동기화 대기 작업 | 즉시 기록하고 오프라인에서 읽는 작업용 저장소 |
| 서버의 관계형 데이터베이스 | 게시된 공통 콘텐츠·시험 일정, 계정별 학습 기록 전체, 목표·설정, 변경 이력 | 콘텐츠 배포와 기기 간 복원의 기준 |
| 서버의 파일 저장소 | 예문·청해 음성 등 큰 파일 | 파일 주소·버전은 DB에 두고 실제 파일을 제공 |

학습 기록은 **휴대폰과 서버 양쪽**에 보관한다. 온라인에서는 휴대폰 기록을 먼저 갱신하고 서버에 동기화한다. 새 기기에서는 로그인 후 서버 기록을 내려받는다. 동기화 전 기존 기기를 분실하거나 앱을 삭제하면 아직 서버에 올라가지 않은 기록은 복원할 수 없다.

콘텐츠와 시험 일정은 관리자가 서버에서 게시한 값을 기준으로 한다. 앱은 게시 버전을 내려받아 기기에 보관하고 오프라인에서 읽는다. 첫 실행부터 인터넷이 없으면 APK에 포함된 검수된 초기 자료를 보여주고 게스트로 학습할 수 있게 한다. 이때 기록은 해당 휴대폰에만 남으며, 계정 연결과 다른 기기의 기록 복원에는 인터넷이 필요하다. 서버 데이터가 바뀌어도 이미 다운로드한 수업·음성과 학습 기록을 오프라인에서 사용할 수 있다. 마지막 갱신 시점을 표시한다.

## 3. 서버 데이터 모델

서버는 PostgreSQL 같은 관계형 데이터베이스를 우선 후보로 둔다. 표의 `id`는 고유 ID이며, 사용자별 표의 `user_id`는 로그인 계정의 ID다. 날짜와 시각은 구분해 저장한다. 아래는 필요한 최소 구조이며 실제 SQL과 인덱스는 구현 단계에서 확정한다.

### 계정과 학습 콘텐츠

| 표 | 주요 필드 | 목적 |
| --- | --- | --- |
| `users` | `id`, `created_at`, `status` | 계정의 내부 식별자. 비밀번호 원문은 저장하지 않는다. 인증 서비스 사용 시 서비스의 사용자 ID와 연결한다. |
| `courses` | `id`, `level`, `title`, `status`, `version`, `published_at` | 입문·N5·N4·N3 등 과정. 등급은 새 과정으로 확장한다. |
| `lessons` | `id`, `course_id`, `sort_order`, `title`, `body`, `status`, `content_version` | 수업 본문과 안정적인 ID·순서. |
| `items` | `id`, `lesson_id`, `kind`, `prompt`, `explanation`, `content_version` | 단어·문법·문제·해설 등 학습 항목. 선택지와 정답은 종류에 맞는 구조로 저장한다. |
| `media_assets` | `id`, `item_id`, `file_path`, `file_version`, `license_note` | 음성 등 파일의 위치·버전·출처. 실제 파일은 파일 저장소에 둔다. |
| `content_revisions` | `id`, `entity_type`, `entity_id`, `editor_user_id`, `changed_at`, `before`, `after` | 콘텐츠 수정·게시 이력. |

첫 APK를 만들기 전에 서버에 게시 콘텐츠를 저장하고 콘텐츠 조회 API와 관리자 게시 기능을 구현한다. APK에는 시작 학습에 필요한 게시 버전의 사본을 포함한다. 이후 콘텐츠 변경은 관리자 게시 → 서버 버전 증가 → 앱 다운로드 → 로컬 교체 순서로 반영한다. 앱에 포함된 콘텐츠 ID와 서버 ID는 일치시킨다. 콘텐츠의 제목이나 순서가 바뀌어도 학습 기록의 ID를 임의로 재사용하지 않는다. 학습 기록이 참조하는 항목을 삭제하거나 정답 의미를 바꿀 때는 이전 버전과의 호환·이력 보존 규칙을 적용한다. 앱이 해석할 수 없는 새 콘텐츠 형식은 APK 업데이트가 필요할 수 있다.

### 사용자별 기록

| 표 | 주요 필드 | 고유 조건 및 용도 |
| --- | --- | --- |
| `user_goals` | `user_id`, `target_exam_id`, `updated_at` | 사용자당 현재 목표 1개. 목표 시험일 변경 가능. |
| `lesson_progress` | `user_id`, `lesson_id`, `status`, `completed_at`, `updated_at` | `(user_id, lesson_id)`당 1행. 수업 완료·이어보기. |
| `item_progress` | `user_id`, `item_id`, `state`, `last_studied_at`, `updated_at` | `(user_id, item_id)`당 1행. 단어·표현별 학습 상태. |
| `review_state` | `user_id`, `item_id`, `due_at`, `interval`, `last_result`, `updated_at` | `(user_id, item_id)`당 1행. 다음 복습 시점. |
| `quiz_attempts` | `id`, `user_id`, `question_id`, `answer`, `is_correct`, `answered_at` | 실제 풀이 이력. 재전송해도 중복되지 않는 `id` 사용. |
| `user_settings` | `user_id`, `show_korean_pronunciation`, `notifications_enabled`, `updated_at` | 계정에 따라 복원할 설정만 저장. 기기별 설정은 별도 처리. |

진도율, 오늘의 복습 개수, 연속 학습일 같은 값은 위 기록으로 계산한다. 성능상 집계값을 저장하더라도 원본 기록에서 다시 계산할 수 있게 한다. 문제의 정답·해설이나 수업 본문을 사용자 행마다 복사하지 않는다.

### 시험 일정과 관리자

| 표 | 주요 필드 | 목적 |
| --- | --- | --- |
| `exam_sessions` | `id`, `exam_name`, `year`, `round`, `region`, `exam_date`, `status` | 회차·지역별 시험일. 공개 전 `draft`, 공개 후 `published`. |
| `registration_periods` | `id`, `exam_session_id`, `kind`, `starts_at`, `ends_at`, `timezone` | 일반·추가 접수 기간. 시각과 시간대 포함. |
| `schedule_sources` | `id`, `exam_session_id`, `source_url`, `checked_at`, `note` | 관리자가 확인한 공식 공지와 확인일. |
| `schedule_revisions` | `id`, `exam_session_id`, `editor_user_id`, `changed_at`, `before`, `after` | 일정 수정·게시 이력. |
| `admin_roles` | `user_id`, `role`, `granted_at` | 콘텐츠·일정 편집·게시 권한. 일반 사용자와 분리. |

시험 일정은 연도나 월을 코드에서 2026년으로 고정하지 않는다. 앱은 받은 회차의 최소·최대 날짜에 맞춰 달력 범위를 만든다. 접수 기간이 지역마다 다를 수 있으므로 `region`을 두고, 공식 공지에서 확정되지 않은 날짜는 예상값으로 게시하지 않는다. 공휴일을 보여준다면 시험 일정과 별도 자료로 관리하고 출처·적용 지역을 남긴다.

관리자 화면은 콘텐츠와 일정을 모두 `초안 입력 → 검토 → 미리보기 → 게시` 순서로 운영한다. 일정 게시 시 공식 출처, 시험일·접수 기간의 순서, 중복 회차를 검사한다. 콘텐츠 게시 시 필수 설명·정답·음성 파일·이용 허락을 검사한다. 앱에는 게시된 자료만 제공한다. 관리자가 입력한 내용이라고 해서 앱이 공식 기관과 제휴한 것처럼 표시하지 않는다.

## 4. 앱과 서버의 동기화

1. 학습 행동이 발생하면 휴대폰 SQLite의 해당 기록과 `sync_outbox` 대기 작업을 **하나의 트랜잭션**으로 저장한다. 화면은 로컬 기록을 즉시 표시한다.
2. 인터넷과 유효한 로그인 상태가 있으면 대기 작업을 서버로 전송한다. 각 작업에 고유 `operation_id`를 붙여 재시도해도 서버에 한 번만 반영한다.
3. 서버가 수락한 작업만 대기 목록에서 지운다. 실패한 작업은 남겨 두고 다음 연결 때 재시도한다.
4. 서버의 최신 기록과 게시된 콘텐츠·일정 변경분을 받아 휴대폰 저장소를 갱신한다. 콘텐츠 묶음은 다운로드·검증을 마친 뒤 한 번에 교체해 일부만 바뀐 수업이 보이지 않게 한다. 앱에는 `마지막 동기화 시각`과 `대기 중인 변경`을 표시한다.

수업 완료는 한 기기에서 완료한 사실이 다른 기기의 미완료 상태로 되돌아가지 않도록 병합한다. 문제 풀이 이력은 고유 ID별로 추가한다. 같은 항목을 두 기기에서 각각 복습한 경우에는 단순히 마지막 수정 시각만 비교하면 복습 횟수가 사라질 수 있으므로, 풀이 기록을 먼저 합친 뒤 복습 상태를 다시 계산하는 방식을 권장한다. 목표 시험일과 설정처럼 하나의 현재값을 가지는 항목은 수정 시각·버전을 이용해 충돌을 감지하고, 필요하면 사용자에게 선택을 요청한다. 이 규칙은 구현 전에 테스트 사례로 고정한다.

휴대폰 시계가 틀릴 수 있으므로 서버는 수신 시각과 기록 버전을 부여한다. 학습 발생 시각은 별도로 보존한다. 서버의 시각은 UTC로 저장하고, 접수 마감·달력 날짜는 해당 공지의 시간대(국내 일정은 `Asia/Seoul`)로 해석한다.

## 5. 로그인과 기기 변경

- **첫 APK:** 첫 진입 화면에서 게스트 시작 또는 로그인을 선택한다. 게스트 기록은 기기에만 저장하며, 설정에서 로그인하면 기존 로컬 기록을 계정에 연결할지 안내하고 서버 기록과 병합한다. 계정에 연결되지 않은 기록은 다른 기기에서 복원할 수 없음을 명확히 안내한다.
- **새 휴대폰:** 로그인 후 서버 기록을 다운로드하고 로컬 저장소를 만든다. 이후 오프라인 학습이 가능하다. 첫 로그인과 최초 복원에는 인터넷이 필요하다.
- **로그아웃·계정 전환:** 이전 계정의 로컬 기록을 다른 계정에 보여주지 않는다. 로그아웃 시 미동기화 기록이 있으면 먼저 알리고, 계정별 로컬 자료의 보관·삭제 정책을 제공한다.

앱이 비밀번호 원문을 직접 보관하거나 서버 DB에 평문으로 저장하지 않는다. 로그인 인증과 학습 API 권한 검사는 서버에서 처리한다. 휴대폰에는 필요한 인증 자격 증명만 운영체제의 보안 저장소에 보관한다. 인증 자격 증명과 일반 학습 기록은 분리한다.

## 6. API와 접근 권한

| API 영역 | 동작 | 권한 |
| --- | --- | --- |
| 인증 | 가입·로그인·로그아웃·계정 복구 | 인증 서비스 및 계정 소유자 |
| 학습 동기화 | 내 변경 전송, 내 기록·변경분 조회 | 로그인한 본인만 |
| 콘텐츠 조회 | 게시된 과정·수업·항목·파일 목록과 버전 조회 | 앱 사용자 |
| 일정 조회 | 게시된 시험 일정·출처·버전 조회 | 앱 사용자 |
| 관리자 콘텐츠·일정 관리 | 초안 작성·수정·게시·이력 조회 | 관리자만 |

요청에 들어온 `user_id`를 그대로 신뢰하지 않고 인증된 사용자 ID로 조회·수정 범위를 제한한다. 관리자 API는 서버에서 역할을 확인한다. 관리자 페이지의 화면 숨김만으로 권한을 대신하지 않는다. 모든 통신은 HTTPS를 사용한다. 일정 조회는 조건부 요청이나 버전 번호로 변경이 없을 때 불필요한 다운로드를 줄인다.

## 7. 운영과 용량

용량을 주로 늘리는 것은 계정별 풀이 이력이다. 과정·단어·문제 원본은 공통으로 한 번만 저장하고, 사용자별 진도는 ID와 상태 중심으로 저장한다. `user_id`, `lesson_id`, `item_id`, `answered_at` 등 실제 조회 조건에 맞춰 인덱스를 만든다. 사용자가 많아지면 오래된 풀이 이력의 보존 기간과 요약 정책을 정하되, 진도·복습을 복원하는 데 필요한 원본은 유지한다.

서버 DB는 정기 백업하고 실제 복원 시험을 한다. 계정 삭제 요청에는 사용자별 학습 기록과 인증 정보의 삭제 절차가 필요하다. 관리자 변경 이력과 학습 기록은 목적에 맞는 보존 기간을 각각 정한다. 서버 비용은 사용자 수, 풀이 기록량, 백업 보존 기간을 측정한 뒤 산정한다. 지금 단계에서 대용량 DB를 미리 구매할 필요는 없다.

## 8. 구현 순서와 완료 기준

1. **서버·인증 기반:** DB 스키마, 사용자 인증, 본인 기록 API, 관리자 역할 검사를 만든다. 다른 계정의 기록을 읽거나 수정할 수 없는지 확인한다.
2. **콘텐츠·일정 관리:** 관리자 초안·검토·게시, 콘텐츠·음성 저장, 공개 API와 버전 조회를 만든다. 서버에 실제 게시 자료를 넣고 출처·이용 조건을 확인한다.
3. **앱 로컬 저장:** 게시 자료의 초기 사본을 APK에 포함하고, 받은 콘텐츠·일정과 학습 진도·풀이·복습을 SQLite에 저장한다. 오프라인 첫 실행과 재실행을 확인한다.
4. **양방향 동기화:** 학습 대기 작업, 중복 전송 방지, 연결 복구, 새 기기 복원, 두 기기 충돌을 구현한다. 콘텐츠·일정 수정 후 같은 APK에 갱신 내용이 표시되는지 확인한다.
5. **출시 점검:** 실제 APK에서 로그인·학습·오프라인·재접속·기기 변경, 관리자 게시, 백업 복원, 계정 삭제와 장애 처리를 시험한다. **1~5가 모두 끝나야 첫 APK를 사용 가능한 출시본으로 본다.**

현재 시험 일정 팝업은 2026년 데이터를 코드에 포함하므로 출시 기준을 아직 충족하지 않는다. 첫 출시본에는 온라인 일정 수신·동적 연도 표시와 로컬 보관을 구현한다. 이후 데이터만 바뀌는 경우 새 APK 없이 갱신한다. 학습 기능 자체나 DB/API 형식이 앱과 호환되지 않게 바뀌면 앱 업데이트가 필요할 수 있다.

## 9. 구현 전에 확정할 사항

- 서버·인증 제공자와 운영 비용 한도
- 로그인 방법(이메일, 소셜 로그인 등)과 계정 복구 방법
- 게스트 기록을 계정에 합치는 방식과 중복 기록 처리 규칙
- 첫 APK에 포함할 검수된 최소 학습 콘텐츠와 필수 음성의 범위
- 풀이 이력 보존 기간 및 계정 삭제 정책
- 콘텐츠 제작·검수 담당자, 자료 이용 조건, 시험 일정 입력 담당자와 공식 공지 검증 절차
